## 这次实现的范围

独立源码：`.work/startup-readonly-fix/source`。远程基线：`49e431b5246492c35bb9331b2598e06bfaba0539`，复制时逐一验证 97 个 Git blob。没有合入行存储方案或根目录历史未提交代码。

恢复页新增“只读查看本机数据”。进入后展示原始保存的经营汇总、产品利润、SKU、订单、退款、资金、推广及基础资料，可以分页、按已保存店铺/日期筛选、搜索、查看单条原始字段及导出备份。

这是临时本机记录查看入口，不是完整的正常录入工作台。它不挂载普通业务路由、编辑器、退款观察器或其他自动保存组件，不进行任何经营结算重算。原记录没有的日期/金额不推算；null、零、缺失字段与保存数值精度保持区别。退款/资金原记录没有保存日期时，日期筛选不会为其补造日期。

选择只读会先同步设置写屏障，再取消未结束的读取、dispose 同步 manager，并阻止晚到的云端响应改变视图或清理备份。不会自动标记、删除、重写原草稿；online 事件不触发同步。返回版本核对通过刷新重新读取；不能自动转为编辑状态。

启动时本机读取与云端读取独立完成，本机备份可用时不必等云端大文档请求完成才显示只读入口。云端读取设置前端 30 秒取消上限；未调整数据库超时。读取错误显示可获得的 HTTP 状态、错误码、阶段、耗时；HTTP 200 后前端数据结构异常单独标识。

初次查询禁止自动初始化；有本机备份时，云端零行不会触发空文档写入。本机读取成功且完全没有备份的新账号仍保留原初始化行为。普通已登录账号的正常工作台、结算和版本检查继续使用远程原有逻辑。

## 实际修改文件

- `src/store/workbench.tsx`：只读入口、启动读取状态与取消、账号切换隔离、错误详情、同步写屏障。
- `src/services/supabase.ts`：读取取消信号、禁止初始化选项、读取错误阶段/耗时；归一化和结算公式不变。
- `src/components/ReadonlyWorkbench.tsx`、`src/components/readonly-workbench.css`：独立原记录查看器，没有编辑/导入/保存接口。
- `src/utils/readonlyWorkbench.ts`：结构与账号校验、原记录选择与值显示，不计算金额。
- `tests/workbenchReadonly.test.cjs`：真实 React Provider/读取器挂载测试与真实服务加载函数测试，云端和草稿存储用可计数依赖替代。
- `package.json`、`package-lock.json`：仅增加开发测试依赖 react-test-renderer；生产依赖不增加。

未修改 Layout、SyncNotice、PddAnalyzer、pddLedger、pddCalculations、collectionRefunds 或结算导出。交付 manifest 对照远程基线列出所有改动和未变更业务文件校验。
