# 订单日期回填口径

每日经营行的日期取订单报表的支付时间／订单成交时间。售后和资金流水按完整订单号精确匹配，后续退款、扣款、结算和补回均归属原订单日期；推广费按店铺和推广统计日期归属。

- 有效销售额沿用工作台口径：剔除未发货成功退款、取消订单后，再减去已发货订单的实际退款本金和优惠券冲回。
- 售后表判断成功状态及发货阶段；退款本金、优惠券退款以实际资金流水为准。两张表不会重复扣减金额。
- 订单首次导入并匹配成本时保存单件成本。修改 SKU 成本只影响后续首次导入的订单；重复导入旧订单、回填售后或资金不会重定价。未匹配成本的订单可以补充匹配后锁定。
- 未发货成功退款不计销售额及商品成本；已发货退款仍保留商品成本。推广费及原有产品推广分配不因退款重新分摊。
- 资金净回款仅累计订单经营收入、退款和其他经营扣款／补回，排除推广消耗与资金划转。
- 订单按订单号更新，售后按售后编号更新；资金以规范字段指纹加相同行序号去重，保留同一报表中确实存在的多笔相同流水。
- 未找到订单的售后／资金索引保留待匹配，不归入发生当天；补导订单后自动回填。

## 旧数据首次补导

旧版本仅保存每日汇总，缺少订单号和资金事件索引。为这些日期一次性补导完整订单、售后和资金报表；推广报表可以一起补导，也可以保留原汇总中的推广费。完整订单数和已入账订单覆盖原汇总后才替换该日期数据，避免部分报表清空旧汇总。

首次建立索引时按当时可匹配的 SKU 成本创建成本快照；旧汇总无法还原每单过去使用的 SKU 成本。如历史期间存在不同成本，需在初始化时核对成本数据。完成初始化后，后续成本修改不会改变这些快照。

后续每次可单独导入新订单、推广、售后或资金报表，有重叠日期的重复导入不会重复记账。日期筛选、总览、退款率、趋势和结算导出都按原订单日期统计。

云端保存每日汇总和用于回填、成本锁定、去重的最小计算索引；不保存原始文件、收件人、备注及业务描述。

验证：`npm test`、`npm run build`。页面验证使用隔离的模拟账户与模拟报表，不触及真实业务数据。
